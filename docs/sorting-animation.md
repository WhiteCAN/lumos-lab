# 정렬 과정 애니메이션

정렬 학습 화면(`/`)에서 선택한 알고리즘과 입력 배열을 브라우저에서 실행하고 비교·교환·병합·확정 과정을 재생합니다. 서버가 없어도 애니메이션은 동작하며 기존 `POST /api/algorithms/sort` 호출과 응답 로그는 별도로 유지합니다.

## 조작과 표시

화면은 알고리즘 선택 → 애니메이션 → 입력 및 API 결과 순서입니다. 상단에 6종 알고리즘을 한글·영문 버튼으로 모두 표시하고, 선택 상태와 현재 알고리즘 설명을 함께 제공합니다.

- 재생·일시정지, 이전·다음 단계, 처음으로, 단계 슬라이더, 0.5·1·2배 속도를 제공합니다. 마지막 단계에서는 다시 재생할 수 있습니다.
- 입력 또는 알고리즘 변경 시 재생을 멈추고 첫 단계로 돌아갑니다. 자동 재생은 사용자가 시작합니다.
- 정수 1~100개를 쉼표로 구분합니다. 빈 항목·문자·소수·32비트 정수 범위 밖의 값은 오류로 안내합니다. 100개 제한은 화면 실습 제한이며 API 스키마의 제한이 아닙니다.
- 값은 고유한 원래 번호를 유지하며 이동합니다. 같은 값도 구분하고 음수·0도 표시합니다. 높이는 입력 최솟값과 최댓값에 따른 상대 크기이며 0 기준 수치 축이 아닙니다.
- 비교·교환/병합·확정을 색과 텍스트로 함께 표시합니다. 확정은 이후 위치가 바뀌지 않는 상태입니다. 부분 정렬만 된 삽입·병합 구간은 완료 전 확정으로 표시하지 않습니다.
- 많은 항목은 그래프 내부에서 가로 스크롤합니다. 동작 줄이기 설정은 위치 이동 전환을 없애며 단계 조작은 유지합니다.

## 실행 범위와 Java API의 차이

| 알고리즘 | 브라우저 실행 | Java API와의 관계 |
| --- | --- | --- |
| Bubble | 인접 비교·교환, 매 순회 마지막 위치 확정 | 조기 종료 없는 기존 반복 구조와 동일 |
| Selection | 최솟값 비교·선택 후 교환, 앞 위치 확정 | 기존 구조와 동일 |
| Insertion | 인접 교환으로 앞 정렬 구간에 삽입 | Java의 key 보관·오른쪽 shift 대신 항목 이동을 보이기 위한 변형 |
| Quick | 마지막 값을 피벗으로 제자리 분할, 피벗 위치 확정 | Java는 가운데 값과 left/equal/right 보조 배열 사용 |
| Merge | 두 정렬 구간의 값 비교 후 병합 결과 일괄 반영 | 비교 원리는 같지만 보조 배열에 하나씩 쓰는 과정은 생략 |
| Heap | 최대 힙 비교·교환, 최댓값을 뒤로 이동해 확정 | 기존 heapify 구조와 동일 |

횟수는 브라우저 모형의 값 비교와 서로 다른 위치의 실제 교환만 집계합니다. 인덱스 조건 검사와 자기 자신 교환은 제외합니다. 병합은 교환으로 세지 않습니다. 프레임 수·비교 횟수·실행 시간은 서버 로그나 서버 측 측정값을 뜻하지 않습니다.

## 구현과 검증

- 화면: `frontend/src/app/page.tsx`에서 입력 검증과 기존 API 실행을 유지합니다.
- 재생: `frontend/src/components/sort-animation.tsx`. effect 타이머는 일시정지·단계 변경·컴포넌트 해제 시 정리합니다.
- 알고리즘: `frontend/src/lib/sort-trace.ts`의 `createSortTrace`, `compare`, `swap`, `finalize`에서 브레이크포인트로 상태를 확인합니다.
- 테스트: `frontend/scripts/study-sort-trace.test.mjs`. 6종의 정렬 결과·항목 보존·음수·중복·안정 정렬·확정 위치·비교/교환 횟수·100개 역순·입력 실패 경로를 검증합니다.
- 실행 명령: frontend에서 `npm run test:study`, `npm run test:labs`, `npm run lint`, `npm run build`.
- 브라우저 확인: 재생·정지·단계 탐색·입력 변경·오류 입력·6종 완료, 320/768/1024/1440/2560px 넘침, 동작 줄이기 설정을 확인했습니다. 백엔드 변경은 없으며 이번 작업에서 실제 API 서버 응답은 검증하지 않았습니다.
