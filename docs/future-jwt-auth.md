# 나중에 할 일: 실제 로그인과 JWT 인증 학습

## 현재 결정

2026-09-24: Lab 로그인 기능은 이번 팀 메뉴 변경에서 구현하지 않습니다. JWT 액세스 토큰·리프레시 토큰 학습과 함께 실제 로그인 기능을 붙입니다. 기존 Security/JWT 레퍼런스와 mock 실습은 실제 회원 로그인 연동과 구분합니다.

그전까지 Lab에서는 Admin 메뉴와 `Alt+3`를 숨김·비활성화합니다. 공개 메뉴는 Photo (`Alt+1`)와 Lab (`Alt+2`)이며 새 탭으로 엽니다. 다른 사이트의 로그인 상태를 추측하거나 토큰을 URL로 전달하지 않습니다.

## 학습·구현할 항목

- [ ] 액세스 토큰과 리프레시 토큰의 역할·수명·검증 흐름을 설명하고 실습하기
- [ ] 로그인 → 보호 API 호출 → 액세스 토큰 만료 → 재발급 → 원래 요청 재시도 흐름 구현하기
- [ ] 리프레시 토큰 저장 방식, 회전·재사용 탐지·폐기 정책 정하기
- [ ] 로그아웃 및 만료된 세션 처리, 동시 재발급 요청과 무한 재시도 방지 실습하기
- [ ] 브라우저 저장 위치와 HttpOnly/Secure/SameSite 쿠키, CSRF·XSS 위험 비교하기
- [ ] 서버에서 일반 회원과 관리자 권한을 구분하고 메뉴·단축키에 검증된 상태 연결하기
- [ ] Lumos와 별도 인증을 쓸지 공통 로그인으로 연동할지 결정하기
- [ ] 로컬·개발계에서 정상 로그인, 만료, 재발급 실패, 로그아웃, 권한 부족 시나리오 검증하기

이 목록은 후속 학습 과제이며 인증 구조·API 계약·토큰 저장 정책은 구현 전에 별도로 확정합니다. UI 메뉴 숨김만으로 접근 권한을 보호하지 않습니다.
