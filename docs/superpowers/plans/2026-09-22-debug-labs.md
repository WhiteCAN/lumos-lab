# 학습 페이지 실행·디버깅 실습 구현 계획

목표: 설명 페이지에서 입력값을 바꾸고 실제 코드 실행과 API 응답을 확인한다. 기존 실행 기능은 재사용한다.

구조: Spring Boot의 학습 전용 Controller·Service, 입력 검증 DTO, 프론트엔드 실습 패널을 추가한다. JavaScript 실행 순서는 브라우저에서 관찰하고 실제 지연 API 응답과 연결한다. 인프라가 없는 분산 패턴은 단일 프로세스 실습임을 명시한다.

- [x] 최근 5개 페이지: 순서 있는 Map, 재시도, Promise, 이벤트 루프, CORS 실습.
- [x] 사용자가 선택한 나머지 범위의 기존 실행 기능 조사 및 실습 연결.
- [x] 정상·실패·입력 한계 테스트, backend test, frontend test:study·lint·build.
- [x] 실제 HTTP 요청·브라우저 실행·반응형 검증.
- [x] 향후 정리 요청의 실행 API·디버깅 안내 기준을 AGENTS와 README에 기록.

검토 기준: 하드코딩된 예상 결과를 실제 실행처럼 표시하지 않음, 동시 실행 시 상태 격리, 오류·로딩 노출, CORS 거부 동작, 무제한 지연·루프 방지.

검증 결과: backend 50개 테스트, frontend study 13개·labs 3개, lint·build 통과. 40개 새 실습 연결의 기본 입력을 브라우저에서 실제 API로 호출하여 모두 성공. Promise 부분 실패 후 늦은 응답 수집과 5개 대표 모바일 페이지를 확인했습니다. TDD 페이지의 긴 소스 경로 줄바꿈과 실제 패키지 경로도 수정했습니다.
